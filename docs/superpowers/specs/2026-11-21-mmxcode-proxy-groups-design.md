# 出口组回来了：一个组能有多条地址，坏了自动换 —— 设计

日期：2026-11-21
状态：待定。
上一份：`docs/superpowers/specs/2026-11-21-mmxcode-proxy-outlets-design.md`（出口只剩两级）。
计划：`docs/superpowers/plans/2026-11-21-mmxcode-proxy-groups.md`。

## 1. 原话

用户说：

> 我们是不是可以增加一个代理组的能力，然后代理组能有多个代理ip，也能有单个，然后有一
> 个全局的代理，也能让用户设置？

问了三件事，答的是：

1. 一个组里有多个地址的时候，请求该怎么挑？—— **故障转移**。
2. 组存在哪里、谁来改？—— **数据库 + 控制台/API**。
3. 全局代理要不要也变成一个组？—— **要**，多个地址、页面上能改。

合起来是三件事：

1. **组回来了，但组不再是一个名字配一个地址**：一个组是有序的一串地址（一条也行）。
2. **组里的地址有先后**：第一个通就用它，不通换下一个 —— 故障转移，不是轮询、不是随机。
3. **组存在库里，页面上能改**；全局代理本身就是一个组（保留名 `default`），页面上
   也能改。

上一份规格把组退役了（那是 WARP 的副产品）。这一份把它捡回来，换了个样子：**组是
用户自己管的一组出口地址，不在配置文件里，在库里。**

## 2. 为什么现在改

用户的 resin 有正向的也有反向的，好几个出口；实际用起来总有一个会挂。挂在全局默认
上的话，挂掉的是**所有**号；挂在账号自己的地址上，就得一个号一个号地改。

组就是为这个来的：**一组出口，按顺序用，坏了往下换**。

现在的出口只有两级（账号自己的地址 → 全局默认），中间没有「几个地址轮着来」的位置。
全局默认那条路一挂，所有号一起挂 —— 而且现在网关的做法是把同一个账号的重试预算
全烧在那个死地址上（见第 6 节）。

## 3. 组是什么

新表：

```sql
CREATE TABLE proxy_groups (
  name       TEXT PRIMARY KEY,
  urls       TEXT NOT NULL,        -- JSON 数组，有序
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
)
```

- **组的身份就是它的名字**。账号行上的 `proxy_group` 那一列存的就是组名 —— 这一列
  数据库里一直都在（上一版只是清空了它，没有删列：删列要重建整张表，那张表上有触发
  器、有一百多个号在用），现在重新有用了。
- **保留名 `default`**：全局组。它是全局默认出口，页面上显示成「全局默认」，删不掉
  （名字被占了就没法再建一个全局组）。
- 地址在 `urls` 里，是一个 JSON 数组，**顺序就是故障转移的顺序**。一条地址的组也
  是组（用户说「也能有单个」）。
- 地址里的账号密码是秘密，跟账号自己的地址一个待遇：库里明文存（跟
  `accounts.proxy_url`、`egress_health.url` 一样），页面上和命令行上打出来的时候
  去掉凭据。

**为什么用一张表加一个 JSON 数组，而不是「组一张表、成员一张表」**：组只有几条地
址，成员表要两张表、两个增删改的面、一次 join。数组在页面上就是一个文本框（一行
一个地址），改组就是改一个字符串。组要是哪天长到几十条地址再说。

**组的顺序是它的意义**：第一个地址是主路，后面的都是备路。改顺序就是改主备。

## 4. 出口怎么算

```
账号自己的地址（accounts.proxy_url）
  → 账号指着的组（accounts.proxy_group）
  → 全局组（proxy_groups 里那个 default）
  → 直连
```

- 账号自己的地址和组**二选一**：页面上选了组就把地址框清掉，填了地址就把组清掉。
  命令行上 `--url` 和 `--group` 也是二选一，同时给就报错。库里两个字段都留着，但
  界面不造出两个都有的状态。
- 每一级都能有**多条**地址（组），按第 5 节的顺序挑。第一级是账号自己的地址 —— 一
  条。
- 一个都没有就是直连。直连是最后一级，不是错。

**为什么全局组排在账号自己的组后面**：账号自己指的组是这个人特意挑的，比全局的那
一组更具体。

**账号自己的地址坏了，往哪走**：往下 —— 它的组（如果还指着一个）、全局组、直连。
这一条跟上一版的「地址压过一切、坏了就报错」不一样，是有意改的：多级出口的意义就
在于有一级不通时下面还有一级。**换地址这件事要说一声**（网关在日志里说），不然看
着是「那个号走了 A 路」，其实是走了 B 路。

## 5. 组里挑哪个

`egress_health` 这张表本来就是**按地址**记的（`url` 是主键，一条地址一条记录：
通不通、什么错、什么时候探的）。组里的地址也进这张表 —— 健康检查查的地址从「全局
默认 + 账号自己写的」扩成「全局组 + 每个组 + 账号自己写的」。

组内的顺序：

1. **探通过的**（按组里的顺序）
2. **没探过的**（按组里的顺序）
3. **探失败的**（按组里的顺序）—— 最后才用，因为探的结果可能是旧的（探完到现在过
   了很久，代理早就活了）

所以「第一个地址通就用它，不通换下一个」这条，落成了一张已有的表加一个排序。

**探活还是那个探法**：每个地址发一个请求到探活目标（`egress.Check`），带自己的超时。
一轮两分钟（`schedule.egress_health`）。

## 6. 请求失败时当场换

现在网关内层那个重试循环里，网络错误（上游一个字节都没回）只是 sleep 一下，然后
拿**同一个** transport 再来一次 —— 连着 `attempts` 次都用那个地址。地址死了的话，
这一轮的预算全烧在这儿，然后才换号；而换的号多半还走同一个全局代理。

改成：

- 账号的出口还有下一个候选地址 → **立刻换下一个地址重来**（不 sleep —— 不是上游
  慢，是这条路不通，等没有用）。
- 候选走完了 → 按现在的路子 backoff 后重试，最后才换号。

候选从哪来：`Manager.Candidates(ctx, accountID)` 给出这个账号的有序地址表（自己的
地址 → 它的组 → 全局组），网关自己拿 transport。

## 7. 哪个地址算坏了

请求失败时把地址记成坏的 —— **但只记「根本没连上」那一种**：

| 错 | 算代理坏吗 |
|---|---|
| `dial` 失败（连不上、地址不存在、代理那边拒了连接） | 算 |
| `proxyconnect` 失败（连上了但 CONNECT 没成） | 算 |
| 域名解析不了（代理自己的域名） | 算 |
| 读超时、写超时 | 不算 —— 上游慢，不是代理的错 |
| TLS 握手错 | 不算 |
| 上游回了 502/503 | 不算 —— 那是回答，不是错 |

规则写在 `egress` 包里一个函数里（`Unreachable(err) bool`）：错误链里有
`*net.OpError`（Op 是 `dial` 或 `proxyconnect`）或者 `*net.DNSError` 才算。

**为什么不全记**：全记的话，一个上游慢导致的超时会把它走的那条代理记成坏的，下
一个请求就绕开它 —— 一次抖动就把一条好路踢掉了。全不记的话，一个死掉的代理在下一
轮健康检查（两分钟）之前，每个请求都要先撞它一次，而撞它是 30 秒的连接超时。

**记了之后会好**：健康检查每两分钟重新探一遍，探通了就把坏记号擦掉。

## 8. 开机时

### 8.1 全局组

库里有 `default` 这个组就用库里的；没有就用配置里的 `proxy.default` 种一个，并在
stderr 上说一声：

```
warning: the global group was made from proxy.default in the configuration.
The configuration's proxy.default does not count any more — change the global
group on the page.
```

配置里没有 `proxy.default`（空）就不建这个组 —— 全局组没有地址就是直连。

### 8.2 配置里的老键 `proxy.groups`

上一版把这个键当退役键（认，但不用）。现在它是**种子**：

| 配置 | 库里 | 结果 |
|---|---|---|
| `proxy.groups` 里有 `clash` | 没有 `clash` 这个组 | 用配置里的地址建一个 `clash` 组（一条地址） |
| `proxy.groups` 里有 `clash` | 有 `clash`（页面上建过、改过） | 库里的算数，stderr 上点这个名 |
| `proxy.groups` 里有 `clash` | 有 `clash`，但组里的地址跟配置里不一样 | 库里的算数，stderr 上点这个名 |

**为什么留这个种子**：老库里有一批账号指着组名（上一版说过，用户本机那份库里有 17
个号指着 `clash`）。组回到库里，这些号不用动就还指着 `clash` —— 升级前后走的路一样。
没有这个种子，那些号会突然落到全局默认去（出口变了，而且没人知道）。

stderr 上要说的（说一次，不说就有人以为配置里那个还在管事）：

```
warning: the group "clash" in the configuration was already in the database.
The one in the database counts. That part can be taken out of the configuration file.
```

### 8.3 上一版那个「把组名搬成账号自己的地址」的收拾

**退役**。组回来了，不用搬了：账号行上的组名继续指组。

但**搬过的地方不改回来**：已经跑过上一版的库，账号行上那些组名已经没了、地址已经
写上去了 —— 那是用户自己那条路（`clash` 的地址），不动它。用户想要组的形式，在页
面上建一个组、把账号指过去就是了。

### 8.4 组名对不上的账号

账号指着一个库里没有的组：**组名留着**（不清掉 —— 人等下在页面上把组建出来，这个号
就自己回去了），出口按第 4 节的链条往下走（全局组 → 直连）。开机时在 stderr 上说一
声是哪些账号：

```
warning: 3 account(s) point at a group that is not in the database (hk).
They follow the global group for now.
```

### 8.5 上一版把 `proxy_group` 那一列清空的事

**不做了**。`SetAccountProxy` 以前顺手写 `proxy_group=''`（组退役了，列也就没用了）。
现在这一列有用了，**写地址不动组**。

## 9. 组怎么改

### 9.1 页面

- **出口页**：上面加一段「组」——
  - 每个组一行：名字（`default` 那行标着「全局默认」）、地址条数、每条地址（去掉凭
    据）带健康状态（通/不通/没探过）、改按钮、删按钮（`default` 没有删按钮）。
  - 改组：一个文本框，一行一个地址，存回去就是整组。
  - 删组：确认框里写清楚「5 个账号会回到全局」。
  - 下面还是账号自己写的那些地址（去掉重复的），跟今天一样。
- **账号页**：每行多一个「出口组」下拉框（空 = 跟随全局；选项是库里的组）。选了组
  就把「单独代理地址」那个框清掉，填了地址就把下拉框清空。

### 9.2 API

| 接口 | 做什么 |
|---|---|
| `GET /api/proxy-groups` | 组列表（含每条地址、健康状态、有几个账号指着） |
| `POST /api/proxy-groups` | 建组或改组：`{"name": "...", "urls": ["...", ...]}` |
| `DELETE /api/proxy-groups?name=...` | 删组（指着它的账号回到全局） |
| `PATCH /api/accounts/{id}` | 多一个字段 `proxy_group`（跟 `proxy_url` 二选一） |

组名已经有了就报 409（改组用 POST，`name` 一样就是改）。改 `default` 组的地址是
允许的。

### 9.3 命令行

```
mmxcode groups list                  # 组、地址（去掉凭据）、有几个账号指着
mmxcode groups set --name X --url A --url B   # 建组或改组（--url 可以给多次）
mmxcode groups rm --name X           # 删组
mmxcode accounts proxy <id> --group X   # 账号指这个组（和 --url 二选一）
```

`accounts proxy --url` 还在（设置地址，同时清掉组）。`accounts list` 多一列「出口
组」。

## 10. 不做什么

| 不做 | 为什么 |
|---|---|
| 轮询、随机 | 用户说的是故障转移 |
| 组的地址做负载统计、每个地址的流量账 | 现在没人问这个 |
| 删掉 `accounts.proxy_group` 那一列 | SQLite 删列要重建表，那张表上有触发器和一百多个号 |
| 组放进配置文件当主要的家 | 用户说了：库里，页面上改 |
| 组里的地址做健康检查以外的探活（比如定期主动 ping 端口） | 一个 HTTP 请求就够了 |
| 请求失败时把地址永久记成坏的 | 健康检查每两分钟重新探，探通了就擦掉 |
| 全局组改名 | `default` 是保留名，改了名「全局」就不全局了 |

## 11. 行为变了的地方

1. **出口多了一级**：账号自己的地址 → 它的组 → 全局组 → 直连。
2. **全局默认从「一个地址」变成「一个组」**：配置里的 `proxy.default` 只在第一次开
   机时种出全局组；之后全局组在库里，页面上改。
3. **`proxy.groups` 从退役键变成种子键**：库里有同名组就以库里的为准。
4. **账号的组名不再被清空**：指着一个库里没有的组，就落到全局（stderr 上点名）。
5. **网络错误会换地址重试**：不是拿同一个死地址把预算烧完。
6. **地址的健康多了一条来源**：请求失败（连不上那种）也会记一笔。

## 12. 怎么量

- **组能建能改能删**：页面上建一个组，写两条地址 → 组里有两条；改组 → 地址变了；
  删组 → 组没了指着它的号回到全局。
- **组里挑的是活着的那条**：组里第一条是死地址、第二条是活的 → 请求走第二条。
- **请求失败当场换**：第一个地址连不上 → 同一个请求用第二个地址答上了。
- **全局组是组**：配置里的 `proxy.default` 开机种出全局组；之后在页面上加一条地址
  → 两个地址都在用。
- **老部署不受影响**：一份带 `proxy.groups: {clash: ...}` 的配置 + 一个指在 `clash`
  上的账号 → 开机之后库里有了 `clash` 组，那个账号还指着它。
- **地址和组二选一**：页面上选了组，地址框是空的；填了地址，下拉框回到空。
- **命令行**：`groups list` 看得到组；`accounts proxy --group` 好使。

## 13. 风险

| 风险 | 怎么办 |
|---|---|
| 组的地址在库里，账号的指向也在库里，两处对不上 | 对不上的那个号落到全局，并在 stderr 上点名；组名不清掉 —— 人把组建出来它就自己回去了 |
| 全局组被页面上的操作清空了 | 全局组没有地址就是直连 —— 跟今天没有全局默认一样，不是新的错法 |
| 换地址悄悄发生了 | 网关在日志里说一声换到了哪个地址 |
| 健康表是旧的（两分钟内的旧） | 探失败的地址排在最后，探过期的地址照样能用 |
| 一次抖动把好路记成坏的 | 只记「根本没连上」的错；健康检查两分钟内擦掉 |
| 组里的地址带凭据，页面上漏出来了 | 去掉凭据再打出来（跟账号自己的地址一个待遇） |
