# 出口只剩两级：WARP 出项目，出口组退役 —— 设计

日期：2026-11-21
状态：待定。
计划：`docs/superpowers/plans/2026-11-21-mmxcode-proxy-outlets.md`。

## 1. 原话

用户说：

> 算了我们的项目中把wrap摘除了，我们复用resin的服务就好了。

问了两件事，答的是：

> 我们项目只留全局代理设置，和单账号独立设置代理，让用户自己设置。resin有正
> 向和方向的代理。

> 不需要，让用户自己在控制台，或者api设置。

合起来是三件事：

1. **WARP 出项目**：compose 里那个 WARP 容器、配置里预置的 `warp` 组、文档里
   那一节，全都去掉。用户自己有 resin（正向的和反向的都有），用户自己填地址。
2. **出口组这个概念退役**：项目里只留「全局默认出口」和「单账号自己的出口地址」
   两级。组（几个账号共用一条出口）没有了。
3. **地址由用户在控制台或者 API 上填**：项目不预置任何出口，也不替用户写地址。

## 2. 为什么现在改

WARP 那一套是当初为了「给一部分账号换个出口」而做的：compose 起一个 WARP 容
器，它在里面开一个 SOCKS5 口子，配置里预置一个叫 `warp` 的组指向它，账号指
到那个组就走 WARP。

用户现在有 resin 了 —— 自己的服务，正向的反向的都有 —— 所以 WARP 那一套不必
要了。而「出口组」这个概念本身是为了 WARP 才有的：一个组就是一个名字，指向一
个地址；WARP 走了，组也就没有留下的理由。

**组留着有代价，不只是多一个下拉框**：

- 出口的找法是三级的（账号自己的地址 → 账号指的组 → 全局默认），多一级就多一
  处能出错的地方。组名写错而默默落到全局默认，是最坏的一种错：看着跑通了，其
  实请求根本没走要去的那条路。CLI 和页面上都得为此写校验。
- 组的地址在配置里，账号的指向在库里，两处要自己对得上。改组名就得改库。

**只留两级之后**：出口要么是账号自己写着的那个地址，要么就是全局默认。两处都
在能看见的地方 —— 账号的地址在页面上写着，全局的在配置文件里写着。

## 3. 出口只剩两级

```
账号自己的地址（accounts.proxy_url）  →  全局默认（proxy.default）  →  直连
```

- 账号自己的地址写在数据库里，页面上每一行都能改，命令行也能改。
- 全局默认写在配置文件里。
- 两个都没有就是直连。直连是最后一级，不是错。

**组的痕迹全清**：配置里的 `proxy.groups`、账号行里的 `proxy_group`、页面上的
下拉框、命令行上的 `--group`、导入带的出口组、健康检查按组名查的那一套。

## 4. 配置：老键还认，但退役了

配置文件里两个老键还得能读：

| 键 | 为什么还得认 |
|---|---|
| `proxy.groups` | 老部署的配置文件里有它。加载器认不出的键是错字，直接报错 —— 那台机器就起不来了。而网关起不来，那台机器上的号就全废了 |
| `batch.group` | 同上 |

**认，但不用**。`proxy.groups` 只有一处还用得上：开机的时候读一次（见第 5 节）。
`batch.group` 一个字节都用不上了 —— 导入不再有「走哪个组」这件事。

读完之后，网关在 stderr 上说一声：

```
warning: proxy.groups 这个键退役了：账号身上的出口组已经变成账号自己的地址。
这一段可以从配置文件里删掉了。
```

**不说是不行的**：人配了那个键，看不见它没用了，只会以为它还在管事。

## 5. 账号身上那个组名，变成账号自己的地址

老库里，账号行上有一列 `proxy_group`（组名），还有一列 `proxy_url`（地址）。
找出口的规矩是「先看地址、再看组」—— 所以一个指在组上的账号，实际走的是那个组
的地址。

组退役了，那一列组名就没人认了。**开机的时候收拾一次**：

| 账号的样子 | 收拾完 |
|---|---|
| 指在组 `clash` 上，自己没有地址；配置里 `clash` 有地址 | 组名清掉，账号自己的地址写成那个地址 |
| 指在组 `clash` 上，自己已经有地址 | 组名清掉，地址不动（地址本来就压过组） |
| 指在组 `hk` 上，配置里没有 `hk`（配置改过了，组名对不上） | 组名清掉，账号回到全局默认，stderr 上说一声是哪些账号 |

第三种要说出来：那个账号的出口**变了**（它原来走的路没了），人该知道。

收拾是**一次性的**：跑完一次，账号行上就没有组名了，以后开机不用再管。

**列留着**：数据库里那一列不删。SQLite 删列要重建整张表，而这张表上有触发器、有
索引、有一百多个号在用 —— 为了一个已经空了的列去重建它，不值。代码不再写它、
也不再读它（除了这一次收拾）。

## 6. 各个面上的改动

### 6.1 页面

- **账号页**：出口那一格只留「单独代理地址」那个输入框（空 = 跟随全局）。组的那
  个下拉框去掉。
- **出口页**：列的是**在用的**那些地址 —— 全局默认一个，加上各个账号自己写的地
  址（去掉重复的）。健康检查查的就是这几个。
- **测试按钮**：传的是去掉凭据的地址（页面显示的就是它），服务端拿它去对上真
  地址再测。

### 6.2 命令行

- `mmxcode accounts proxy <id> --url <地址>`：去掉 `--group`。
- `mmxcode accounts list`：去掉「出口组」那一列；「代理」那一列照旧：账号自己的
  地址，没有就写全局默认。
- `mmxcode import`：去掉 `--group`。
- `mmxcode relogin`：去掉 `--group`。

### 6.3 导入与重登：走哪条路

- **导入**：走全局默认出口。新账号身上没有自己的地址 —— 它跟着全局默认走，以后
  全局默认改了它也跟着改。（以前导入会把组写在账号身上，等于把当时的出口冻在账
  号上；现在不冻了。）
- **重登**：走这个账号自己的出口 —— 它自己写的地址，没有就全局默认。跟它平常
  干活走的是同一条路。

### 6.4 出口健康检查

查在用的那些地址（全局默认 + 账号自己写的），不再是查配置里的组。

## 7. 不做什么

| 不做 | 为什么 |
|---|---|
| 删掉 `accounts.proxy_group` 那一列 | SQLite 删列要重建表，那张表上有触发器和一百多个号。为一个空了的列重建它不值 |
| 给导入加一个「给新账号写个地址」的口子 | 用户在控制台或者 API 上填 —— 用户是这么说的 |
| 把 WARP 换成 resin 写进 compose | 「不需要，让用户自己在控制台，或者api设置」 |
| 把全局默认冻进每一个账号 | 全局默认改了账号跟着改才对。冻住是「导入时的快照」，那正是组当年带来的毛病 |
| 给老配置里的 `proxy.groups` 报错 | 老部署得能起来。它只是没人用了，不是错 |

## 8. 行为变了的地方

1. **compose 里没有 WARP 了**（那个容器默认本来就不起，但配置和文档里没有了）。
2. **配置里的 `proxy.groups` 不再管事**：开机读一次，把账号身上的组名变成账号
   自己的地址。
3. **账号行上的组名没有了**：页面上、命令行上、库里都不再提组。
4. **导入不再带组**：走全局默认。
5. **重登不再能指定组**：走账号自己的出口。

## 9. 怎么量

- **老配置还起得来**：一份带 `proxy.groups` 和 `batch.group` 的配置 → 网关照常
  起，不报「认不出的键」。
- **组名变成地址**：一个指在组上的账号 → 开机之后它自己的地址是那个组的地址，
  组名没了。
- **组名对不上**：一个指在没人知道的组上的账号 → 组名没了，账号回到全局默认，
  stderr 上有话说。
- **出口只有两级**：`proxy.default` 是 A、账号自己是 B → 那个账号走 B；账号没
  写地址 → 走 A；两个都没有 → 直连。
- **页面上没有组**：账号页里找不到那个下拉框；改地址还是能改。
- **命令行没有组**：`--group` 不存在了；`--url` 好使。
- **健康检查查的是在用的地址**：全局默认 + 账号自己的地址，都被查了一遍。
- **compose 里没有 WARP**：`docker compose config` 里没有那个服务。

## 10. 风险

| 风险 | 怎么办 |
|---|---|
| 老部署起不来（配置里有 `proxy.groups`） | 那两个键还认，只是没人用了 |
| 组名对不上，账号的出口悄悄变了 | 那种账号在 stderr 上被点名；账号页上它的地址是空的（跟着全局默认） |
| 收拾写库的时候正好有别的东西在写 | 跟 `ClearRetiredNotes` 一样：失败只说一声，网关照样起 |
| 全局默认改了，那 17 个从组搬过来的账号不改 | 搬过来的是当时的地址 —— 那正是组的意思。要跟着全局默认改，把账号的地址清空就行 |
| 删错了东西 | 组的地址没丢：它在配置文件里，账号页上也能填回去 |
